The draft is close, but several guarantees still need correction before implementation planning. References below are to the [draft](/Users/jdavidoa91/Dev/hass-cinema-studio/docs/superpowers/specs/2026-10-05-cinema-studio-design.md).

1. **Immutable renders + hard-link import — AGREE with the approach; DISAGREE with recovery/import details.**  
   Hard links survive the old Worker’s atomic replacements. However:
   - Require exclusive creation of render names, file fsync before publication, and a render UUID in the filename. A database restore can roll back `n`; “never decremented” does not prevent path reuse after restore ([lines 112–133](/Users/jdavidoa91/Dev/hass-cinema-studio/docs/superpowers/specs/2026-10-05-cinema-studio-design.md:112)).
   - Quiesce legacy edits/compiles during import, then link, hash and probe the linked file against its corresponding Worker metadata.
   - **Do not convert timing mismatches into zero-margin “verified” timing** ([line 137](/Users/jdavidoa91/Dev/hass-cinema-studio/docs/superpowers/specs/2026-10-05-cinema-studio-design.md:137)). ffprobe duration cannot recover black boundaries. Quarantine mismatches or recompile; allow `legacy_full_file` only for positively identified outputs without margins.

2. **GC rule — DISAGREE until protection semantics are complete.**  
   Ack + 48 hours is reasonable for ordinary forward catalog adoption, provided selection-to-start delay is bounded. Restored snapshots can select retired files *after* retirement grace expires, while the App still holds an earlier protection report. Stat then races GC.

   Require either a shared durable selection-pin mechanism synchronized with GC, or reject retired/unknown renders after restoration until reconciliation establishes protection. Specify pin persistence, expiry, missing-report behavior, consumer identity and maximum selection delay. A six-hour list sent opportunistically is not sufficient.

3. **Stat + size verification — AGREE under an explicit ownership assumption.**  
   Require regular files, safe root containment, no escaping symlinks, and immutable UUID paths. Document that `file_verified` means existence/size checked, not hash-integrity verified. Remove the promised “<1 ms” latency ([line 236](/Users/jdavidoa91/Dev/hass-cinema-studio/docs/superpowers/specs/2026-10-05-cinema-studio-design.md:236)); executor/filesystem latency is variable.

4. **Transition-based activation — AGREE for today’s semantics.**  
   Persisted season comparison is sufficient; occurrence identity is unnecessary here. Clarify that an entire intervening season missed during downtime cannot be detected by comparing endpoints. Define resets for seasons mapping to the same collection, fallback collections, and collection remapping. Serialize activation changes with selection/snapshot swaps; dry-run must not reset activation.

   **DISAGREE with ordered cursor semantics:** “next after last played” differs from production’s first remaining unplayed candidate ([history.py:140](/Users/jdavidoa91/Dev/hass-clips-manager/custom_components/cinema_collections/history.py:140), [153](/Users/jdavidoa91/Dev/hass-clips-manager/custom_components/cinema_collections/history.py:153)). Preserve played-set semantics or explicitly approve the behavioral change for reorder/removal/reappearance.

5. **In-place script edit + fallback — AGREE with preserving the script identity; DISAGREE with the fallback boundary.**  
   The abort dependency justifies revising the `_v2` approach. Initialize the response variable and validate the complete response before any device actions. Fallback must run only during selection/validation, never after playback starts.

   Keep the old season-reset automation enabled during observation: it maintains independent fallback history. Disabling it breaks fallback season-entry behavior ([line 414](/Users/jdavidoa91/Dev/hass-cinema-studio/docs/superpowers/specs/2026-10-05-cinema-studio-design.md:414)).

6. **Response contract — AGREE structurally.**  
   Require finite numbers, specify rounding order/tolerance, include `profile_fingerprint`, and define `timing_verified` as provenance plus invariant validation—not merely successful duration probing. Document supported contract versions and error behavior.

7. **Phases/migration — DISAGREE with current import/verification sequencing.**  
   The actual history key is entry-specific: `cinema_collections.<entry_id>.playback_history` ([__init__.py:97](/Users/jdavidoa91/Dev/hass-clips-manager/custom_components/cinema_collections/__init__.py:97)). Import history after catalog import and refresh it at cut-over. Random dry-runs cannot guarantee matching picks; compare manifests by clip ID instead.

   Add selftest coverage of the **entire replacement block including fallback**, a documented observation exit gate, and eventual compile-automation/native-season cut-over.

These corrections block implementation planning.
